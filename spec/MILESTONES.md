# MILESTONES — משחק Simon

התוכנית מבוססת על [PRD.md](PRD.md), [ARCHITECTURE.md](ARCHITECTURE.md) ו-[DESIGN.md](DESIGN.md). היא מחלקת את המימוש לחמש אבני דרך תלויות זו בזו, ללא לוחות זמנים. הראשונה מקימה תשתית הכרחית; הבאות מספקות יכולות משתמש שלמות עד לפריסה.

## Development Execution Rules — כללי ביצוע הפיתוח

הנחיות מחייבות ל-AI המבצע את הפיתוח:

- יש לפתח את ה-Milestones לפי הסדר המוגדר במסמך.
- לאחר השלמת כל Milestone, יש לעצור את הפיתוח ולהציג למשתמש את התוצר שהושלם ואת תוצאות הבדיקות מול כל סעיף ב-Definition of Done, כולל דרך לפתוח או להפעיל את התוצר.
- אין להתחיל בפיתוח ה-Milestone הבא ללא אישור מפורש של המשתמש. היעדר תגובה אינו אישור.
- יש להבחין בין בדיקה שעברה, בדיקה שנכשלה ובדיקה שלא בוצעה. Milestone אינו מושלם כל עוד תנאי חובה שלו לא אומת; יש לתקן במסגרת אותה אבן דרך או לציין במפורש מה חסר להשלמתה.
- אם בדיקה מחייבת מכשיר או גישה לחשבון שאינם זמינים ל-AI, יש להכין תוצר ניתן לבדיקה והוראות קצרות למשתמש, ולתעד את התוצאה לאחר ביצועה. אין להציג אמולציה כהוכחה לבדיקה במכשיר אמיתי.
- בכל אבן דרך יש לממש גם את העיצוב של היכולת הנוספת, לפי DESIGN.md וה-Mockups, ולבדוק את היכולות הקודמות שעלולות להיפגע מהשינוי. אין לדחות את כל העיצוב לסוף.
- אין להוסיף מסכים או יכולות מעבר למסמכי המקור. פרטי מימוש חזותיים שלא הוגדרו, כגון מיקום תוצאת הסיום בתוך הבית, יושלמו במינימום הנדרש ובסגנון הקיים, ויוצגו כבחירות מימוש בסקירת התוצר.

הפרויקט הוא Frontend בלבד. אין הקמת Backend, Database, Authentication, סביבות Supabase או Database Migrations. Development מתבצע מקומית; Production הוא האתר הסטטי ב-GitHub Pages.

## Milestone 1 — בסיס פרויקט ומסך בית מעוצב ✅

**מטרה:** להקים בסיס פיתוח ו-Build שחוזר על עצמו, ולהעמיד מסך בית הניתן לפתיחה ולבדיקה חזותית לפני חיבור המשחק.

**תלות:** אין.

### מה יש לממש

- הקמת Vite בתבנית `vanilla-ts`, TypeScript במצב `strict`, CSS רגיל, Node.js 24 LTS ו-npm. קיבוע תלויות Stable תואמות ו-`package-lock.json`.
- הכנת Vitest ו-Playwright, פקודות Type Checking, בדיקות ו-Build, ושרת Preview לתוצר הסטטי.
- הגדרת מבנה Modules לפי הארכיטקטורה: Engine, Controller, Views, Playback, Audio ו-Navigation, ללא יצירת שכבות שאינן נחוצות בשלב זה.
- מימוש הבית במצב ההתחלתי: ״סיימון״, כפתור ״אודות״, ארבעה כפתורים ב-Grid של 2×2 וכפתור ״התחל״. חיבור הפעולות יושלם באבני הדרך הבאות; מצב זה יוצג למשתמש כתצוגה ראשונית ולא כמשחק פעיל.
- יישום Tokens, RTL, טיפוגרפיה וגימור הכפתורים לפי DESIGN.md. אם משתמשים ב-Heebo, יש לכלול אותו מקומית; אחרת להשתמש ב-Fallback המתועד.
- הוספת `node_modules`, `dist` ותוצרי בדיקות ל-`.gitignore`. ה-Repository המקומי וחיבורו ל-GitHub (ציבורי) כבר קיימים.

### תוצר מצופה

מסך בית מעוצב שנפתח בסביבת Development וב-Preview של `dist`, עם בסיס בדיקות פעיל. זהו שלב טכני מקדים; משחק עובד נמסר באבן דרך 2.

### Definition of Done

- [ ] `npm ci`, `tsc --noEmit` ו-`vite build` מסתיימים בהצלחה בסביבת Node.js שנבחרה.
- [ ] Vitest ו-Playwright רצים בהצלחה; בדיקת הדפדפן מאמתת טעינת הבית ואת ארבע תוויות הצבעים.
- [ ] מסך הבית נבדק חזותית ב-Viewport של מובייל מול ה-Mockup, ללא גלילה אופקית או חיתוך כפתורים.
- [ ] הצבעים ממוקמים נכון: כחול ימין למעלה, אדום שמאל למעלה, צהוב ימין למטה וירוק שמאל למטה; RTL אינו הופך אותם.
- [ ] כפתורי המגע בגודל של לפחות 48px, וטקסטי הממשק בעברית. אין מסגרת טלפון דקורטיבית בתוך האתר.
- [ ] אין תלות בטעינת Scripts או גופנים ממקור חיצוני בזמן Runtime. הקבצים וה-lockfile מנוהלים ב-Git.

## Milestone 2 — משחק מלא מהתחלה ועד תוצאה ומשחק חדש ✅

**מטרה:** לאפשר למשתמש לשחק משחק שלם עם אור, צליל, ניקוד וסיום, בתוך מסך הבית.

**תלות:** השלמת Milestone 1 ואישור המשתמש.

### מה יש לממש

- חיבור כפתור ״התחל״ ל-State Machine ולמצב בזיכרון בלבד.
- רצף מתארך: צבע אקראי אחד בשלב 1, ובכל שלב הבא הוספת צבע אקראי אחד לסוף הרצף הקודם, בהסתברות שווה וחזרות מותרות.
- Playback של הארה וצליל ייחודי לכל צבע באמצעות Web Audio API: 500 מילישניות לפריט ו-250 מילישניות בין פריטים בלבד.
- הזנת תשובה, משוב ללחיצה, נעילת קלט בזמן הצגה ובסיום, ובדיקת הרצף לפי סדר. אין מגבלת זמן לתשובה.
- מעבר בין עשרה שלבים, נקודה על שלב מלא, סיום בטעות הראשונה וניצחון לאחר שלב 10.
- מונה ״שלב · ניקוד״ בין ה-Header ללוח במהלך משחק, ועמעום כפתורי הצבע כשהקלט חסום, לפי DESIGN.md.
- הצגת ״ניצחון!״ או ״המשחק נגמר״, ניקוד סופי וכפתור ״משחק חדש״ במקום כפתור ״התחל״, ללא מסך נוסף או Modal.
- טיפול בחידוש אודיו מתוך מחוות משתמש, בכשל אודיו, בביטול טיימרים וצלילים ובפסילת Callbacks ישנים לאחר סיום או התחלה חדשה.

### תוצר מצופה

משחק עובד מקצה לקצה במסך הבית: התחלה, הצגת רצפים, תשובות, תוצאה ומשחק חדש. מסך אודות והניווט אליו עדיין ממתינים לאבן דרך 3.

### Definition of Done

- [ ] Vitest מאמת רצפים באורכים 1–10, שכל שלב שומר את הרצף הקודם ומוסיף צבע אחד, חזרות מותרות והיעדר ניסיון לכפות גיוון.
- [ ] בדיקות עם Random נשלט מאמתות כישלון ללא ניקוד חלקי, מעבר שלב עם נקודה אחת וניצחון בדיוק בניקוד 10.
- [ ] Fake Timers מאמתים את משכי ההארה וההפסקה, פתיחת הקלט רק בסיום ההצגה וביטול פעולות ישנות. אין Timeout לתשובה.
- [ ] לחיצות בזמן הצגה או לאחר סיום אינן משנות תוצאה; לחיצות מהירות אינן מזכות בניקוד כפול.
- [ ] Playwright משלים תרחישי ניצחון, כישלון והתחלה מחדש על Build, עם מקור Random נשלט לצורכי בדיקות בלבד.
- [ ] ״משחק חדש״ מתחיל שלב 1 בניקוד 0. רענון מחזיר למצב ״התחל״, ללא שמירת המשחק ב-Web Storage או ב-Database.
- [ ] ארבעת הצלילים מובחנים, ונבדק משוב אור וצליל יחד. כשל בחידוש אודיו אינו מקדם שלב או נחשב לטעות במשחק.
- [ ] המונה מציג את השלב והניקוד הנכונים במהלך המשחק ואינו מוצג לפני התחלה. כפתורי הצבע מעומעמים כשהקלט חסום.
- [ ] מצבי Rest, Active ותוצאה תואמים את השפה העיצובית הקיימת. Type Checking ו-Build עוברים.

## Milestone 3 — אודות, ניקוד והשהיה בטוחה במובייל ✅

**מטרה:** להשלים את היכולת לצפות בחוקים ובניקוד ולחזור למשחק בלי לאבד התקדמות, גם לאחר הפרעת Lifecycle.

**תלות:** השלמת Milestone 2 ואישור המשתמש.

### מה יש לממש

- מסך ״אודות״ עם ״חזרה למשחק״, התווית ״הניקוד שלך״, הניקוד מאותו State, מפריד וכותרת ״חוקי המשחק״ עם כל שש פסקאות החוקים מ-DESIGN.md.
- Hash Routing בין הבית לאודות, לרבות ניווט באמצעות פעולות הדפדפן. בטעינה חדשה חוזרים לבית גם כאשר הכתובת מכילה את Hash של אודות.
- השהיה במעבר לאודות: עצירת צלילים, כיבוי הארות, ביטול Playback ואיפוס תשובה חלקית, תוך שמירת ניקוד, שלב ורצף.
- בחזרה לבית: הצגה מלאה של אותו רצף, ללא הגרלה חדשה או הוספת נקודה. טיפול נפרד בביקור באודות לפני התחלה ולאחר סיום, בלי להתחיל משחק אוטומטית.
- טיפול ב-`visibilitychange` לפי ה-PRD: הפרעה למשחק פעיל עוצרת אותו ומשאירה אותו בבית עם כפתור ״המשך״; לחיצה עליו מחדשת אודיו ומציגה את הרצף מחדש.
- עיצוב אודות לפי ה-Mockup, עם גלילה אנכית כאשר נדרש, ללא הקטנת טקסט החוקים כדי לכפות התאמה למסך.

### תוצר מצופה

שני המסכים פועלים יחד, עם ניקוד וחוקים מעודכנים והשהיה בטוחה. המוצר שלם מבחינת זרימות המשחק והניווט, לפני הוספת התקנה ו-Offline.

### Definition of Done

- [ ] הניקוד באודות הוא 0 לפני התחלה, מעודכן במהלך משחק ונשאר סופי לאחר סיום; אין היסטוריה.
- [ ] כל שש פסקאות החוקים מוצגות במלואן ובסדר הנכון, ב-RTL וללא חיתוך אופקי.
- [ ] נבדקים מעבר לאודות באמצע הצגה ובאמצע תשובה, חזרה והצגת אותו רצף מתחילתו. השלב והניקוד אינם משתנים.
- [ ] מעבר מהיר וחוזר בין המסכים אינו יוצר השמעות מקבילות, הארות תקועות או Callbacks המשנים משחק מושהה.
- [ ] ביקור באודות וחזרה לפני התחלה או לאחר תוצאה משמרים את המצב המתאים, ללא הפעלת שלב נוסף.
- [ ] נבדקים חזרה דרך הדפדפן, טעינה חדשה בכתובת אודות ורענון בכל אחד מהמסכים; טעינה חדשה מאפסת לבית ולניקוד 0.
- [ ] נבדקים מעבר לרקע וחזרה: ה-Playback נעצר, מוצג ״המשך״, ולחיצה עליו מציגה שוב את אותו רצף ללא שינוי בשלב או בניקוד.
- [ ] שני המסכים נבדקים חזותית מול ה-Mockups ב-Chromium במצב מובייל; בדיקות המשחק, Type Checking ו-Build עוברים.

## Milestone 4 — משחק מותקן ופעולה ב-Offline

**מטרה:** לאפשר התקנת PWA ושימוש בשני המסכים ובכל המשחק ללא רשת לאחר הכנה ראשונית מוצלחת.

**תלות:** השלמת Milestone 3 ואישור המשתמש.

### מה יש לממש

- `vite-plugin-pwa` עם Workbox `generateSW`, Manifest בעברית וב-RTL, מצב `standalone` ואייקונים לפי הארכיטקטורה.
- Base, `id`, `start_url`, `scope`, נתיבי משאבים ו-Navigation Fallback תואמים ל-Project Site ב-GitHub Pages.
- Precache מלא של App Shell, Bundles, CSS, Manifest, אייקונים, Workbox Runtime וגופן מקומי אם נכלל.
- רישום Worker ומעקב אחר מוכנות ל-Offline על סמך הצלחת ההתקנה וה-Cache. כשל Cache אינו מונע משחק שכבר נטען ואינו מוצג כהצלחה.
- מדיניות עדכון ללא רענון כפוי (`registerType: 'prompt'` בלי לקרוא לעדכון). אין Dialog עדכון.
- נתוני המשחק נשמרים בזיכרון בלבד.

### תוצר מצופה

Build סטטי מוכן להתקנה ולמשחק Offline, שנבדק דרך localhost ובנתיב המדמה את נתיב ה-Production. בדיקת התקנה באתר החי תושלם באבן דרך 5.

### Definition of Done

- [ ] Manifest ואייקונים נטענים מתוך ה-Base הנכון; ה-Worker מוגבל ל-Scope של הפרויקט.
- [ ] בתרחיש בדיקה מבודד על Build אמיתי: מבצעים טעינה ראשונה, ממתינים ל-Precache ולשליטת Worker, מנתקים רשת וטוענים מחדש בהצלחה.
- [ ] ב-Offline ניתן להתחיל ולסיים משחק, להשמיע צלילים, לצפות בחוקים ובניקוד, לחזור למשחק ולהתחיל חדש.
- [ ] רענון ב-Offline מאפס את המשחק ומחזיר לבית. Cache Storage אינו שומר ניקוד, רצפים או היסטוריה.
- [ ] אין משאבי Runtime הכרחיים ממקור חיצוני.
- [ ] Playwright מריץ בדיקות Offline כאשר Service Workers פעילים; בדיקות המשחק והניווט, Type Checking ו-Build עוברים.

## Milestone 5 — GitHub Pages, פריסה אוטומטית ואימות במכשירים

**מטרה:** להעמיד את המוצר באתר HTTPS חי, עם תהליך פריסה חוזר ואימות חוויית השימוש וההתקנה בנייד.

**תלות:** השלמת Milestone 4 ואישור המשתמש.

### מה יש לממש

- הגדרת GitHub Pages עם Source מסוג GitHub Actions ב-Repository הציבורי הקיים. את הפעולה בחשבון מבצע המשתמש, בהדרכה צעד אחר צעד.
- Workflow שרץ בכל Push ל-`main` בסדר המוגדר בארכיטקטורה: `npm ci` → `tsc --noEmit` → `vitest run` → `vite build` → Playwright על אותו `dist` → העלאת אותו Artifact → `deploy-pages`.
- הרשאות מינימליות, Environment בשם `github-pages` ו-Concurrency אחד לפריסות.
- אימות האתר החי, התקנה וצליל על מכשירי Android ו-iPhone אמיתיים (בדיקה ידנית של המשתמש לפי הוראות).

### תוצר מצופה

כתובת HTTPS עובדת של המשחק ב-GitHub Pages, פריסה אוטומטית מ-GitHub ותוצאות בדיקה של שימוש רגיל, התקנה, Offline ועדכון גרסה במובייל.

### Definition of Done

- [ ] הקוד וה-lockfile נמצאים ב-GitHub.
- [ ] Push ל-`main` מפעיל Pipeline מוצלח ומפרסם את אותו Artifact שנבדק, ללא Build נוסף.
- [ ] כשל בדיקות או Build מונע Deployment; לפרסום אין צורך ב-Secrets יישומיים או ב-Personal Access Token.
- [ ] האתר החי פועל ב-HTTPS וב-Base הנכון; שני המסכים, המשחק, החוקים, הניקוד והרענון נבדקו בכתובת המפורסמת.
- [ ] התקנה, פתיחה במצב Standalone וטעינה חוזרת ללא רשת לאחר הכנה ראשונית נבדקו ב-Android וב-iPhone אמיתיים, באמצעות מנגנון ההתקנה הנתמך בכל מכשיר.
- [ ] במכשירים האמיתיים אומתו ארבעת הצלילים, מגע, קריאות RTL, נעילה וחזרה מרקע ללא Playback שנותר פעיל או אובדן התקדמות כל עוד הדף נשמר בזיכרון.
- [ ] לאחר פריסת גרסה חדשה, פתיחה מחדש של האתר מקבלת אותה בלי למחוק Cache ידנית.
- [ ] בוצעה סקירה סופית מול PRD.md ו-DESIGN.md: שני מסכים בלבד, מראה תואם, ללא Backend, Database, היסטוריה או תלות ברשת בזמן המשחק לאחר הכנת Offline.
- [ ] למשתמש נמסרו כתובת האתר, קישור ל-Repository, סיכום הבדיקות ומגבלות ידועות אם נותרו. הפיתוח נעצר לסקירתו הסופית.
