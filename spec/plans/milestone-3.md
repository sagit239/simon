# תוכנית — Milestone 3: אודות, ניקוד והשהיה בטוחה במובייל

מבוסס על PRD.md (מסך אודות והשהיה, Edge Cases), DESIGN.md §1.2 ו-ARCHITECTURE.md §2.3–2.7, ועל הקוד הקיים אחרי Milestone 2.

## 1. גישה

- **מצב אחד, שני מסכים.** ה-Controller ממשיך להחזיק State יחיד. נוסף לו `screen: 'home' | 'about'` (נפרד מ-`phase`), ונוסף ל-Engine מצב `paused`.
- **שני מסכים בתוך אותו `#app`.** שני אלמנטי `<main>` נבנים פעם אחת; מוצג רק אחד בכל רגע (`hidden`). אין טעינה מחדש, אין ספריית Routing.
- **Hash Routing פשוט** (`#/` לבית, `#/about` לאודות) ב-Module קטן של Navigation. כל שינוי מסך — מכפתור או מ-Back/Forward של הדפדפן — עובר דרך אירוע `hashchange` אחד, שמודיע ל-Controller. כך אין שני מסלולים שונים לאותה פעולה.
- **השהיה = עצירה מלאה.** מעבר לאודות או הסתרת הדף במהלך משחק פעיל: ביטול Playback, ביטול טיימרים (משוב ומעבר שלב), עצירת צלילים, כיבוי הארה, איפוס התשובה החלקית. השלב, הניקוד והרצף נשמרים.
- **חידוש = הצגה מחדש של אותו רצף.** בלי הגרלה ובלי שינוי ניקוד. החידוש קורה בתוך מחוות משתמש (חזרה מאודות או ״המשך״), עם חידוש אודיו.

## 3. Engine — מצב `paused`

- `pause(state)`: אם `phase` הוא `presenting` או `accepting` → `{ ...state, phase: 'paused', inputIndex: 0 }`. בכל מצב אחר — מחזיר את אותו State.
- `resume(state)`: אם `phase` הוא `paused` → `{ ...state, phase: 'presenting', inputIndex: 0 }`. אחרת — ללא שינוי.
- `pressColor` כבר דוחה כל מצב שאינו `accepting`, ולכן לחיצות ב-`paused` נדחות ללא שינוי.
- `startGame` לא נקרא מ-`paused` (כפתור ״התחל״ אינו מוצג במצב הזה); נוסיף הגנה ב-Controller.

## 4. Controller — זרימה

ViewModel: `{ state, screen, lit, audioError }`.

**`pauseGame()` (פנימי):** קורא ל-`reset()` הקיים (מעלה `runId`, מבטל Playback, טיימר משוב וטיימר מעבר שלב, עוצר צלילים, מכבה הארה) ואז `state = pause(state)`.

**`showScreen(next)`** — נקרא מ-Navigation בכל שינוי Hash:
- אם `next === screen` — לא עושים כלום (הגנה מכפילויות).
- **לאודות:** אם המשחק פעיל → `pauseGame()`. בכל מצב אחר (`idle`, `won`, `lost`, `paused`) — רק עצירת משוב/צליל שעוד רץ וכיבוי הארה, בלי שינוי State. גם `start()` שעדיין ממתין לחידוש אודיו מתבטל (בזכות `runId`), והמשחק נשאר `idle`.
- **לבית:** מעדכן `screen`. אם `phase === 'paused'` → `resume()`. בכל מצב אחר — רק הצגה.

**`resume()`** — ״המשך״ בבית או חזרה מאודות:
- רק כשהמסך הוא הבית ו-`phase === 'paused'`.
- `reset()`, חידוש אודיו (`audio.unlock()`), בדיקת `runId` אחרי ההמתנה.
- כשל אודיו → נשארים ב-`paused`, `audioError = true`. בבית מוצגים הודעת התקלה הקיימת וכפתור ״המשך״ לניסיון חוזר. אין התקדמות ואין טעות.
- הצלחה → `state = resume(state)`, `present()` של אותו `state.sequence` מתחילתו.

**`pageHidden()`** — מ-`visibilitychange` כאשר `document.hidden`:
- משחק פעיל → `pauseGame()`. המסך נשאר כמו שהוא (בית), ובבית מוצג ״המשך״.
- אם כבר באודות — המשחק כבר מושהה, אין שינוי.
- `idle` / `won` / `lost` — רק עצירת צליל ומשוב.
- חזרת הדף לתצוגה (`visible`) אינה מפעילה דבר אוטומטית; ממתינים ללחיצה על ״המשך״.

**`start()`** — ללא שינוי, למעט: מותר רק מ-`idle`, `won` או `lost` (לא מ-`paused`).

ב-`render()` הכפתורים והמסכים משקפים תמיד את ה-State, כך שכל Callback ישן שנפסל לא יכול להשאיר הארה תקועה.

## 5. Navigation

- `currentScreen()`: `#/about` → `about`, כל ערך אחר → `home`.
- **בטעינה:** אם ה-Hash אינו `#/`, מחליפים ל-`#/` עם `history.replaceState` (בלי רשומה נוספת בהיסטוריה). כך טעינה חדשה בכתובת אודות תמיד פותחת את הבית, עם ניקוד 0.
- `goAbout()`: `location.hash = '#/about'` (רשומה חדשה בהיסטוריה, כדי שכפתור Back יחזיר לבית).
- `goHome()` (״חזרה למשחק״): `location.hash = '#/'`. בחירה פשוטה; גם Back מאודות עובד דרך אותו `hashchange`.
- מאזין `hashchange` יחיד → `controller.showScreen(currentScreen())`, ואז גלילה לראש העמוד.
- חזרה דרך Back של הדפדפן אינה תמיד מחוות משתמש שמאפשרת חידוש אודיו. אם החידוש נכשל, המצב נשאר `paused` עם ״המשך״ והודעת התקלה — ראה ADR בסעיף 8.

## 6. Views ועיצוב

### מסך הבית (שינויים)
- ״אודות״ → `goAbout()`.
- כפתור Primary רחב חדש ״המשך״, באותו מקום של ״התחל״, מוצג רק ב-`paused`.
- ב-`paused`: מונה ״שלב · ניקוד״ מוצג (המשחק עדיין קיים), כפתורי הצבע מעומעמים ו-`aria-disabled`.
- הודעת התקלה באודיו מוצגת ב-`idle` וגם ב-`paused` כש-`audioError`.
- המסך מוסתר (`hidden`) כש-`screen === 'about'`.

### מסך אודות (חדש) — לפי DESIGN §1.2 וה-Mockup
- Header באותו רכיב של הבית: ״אודות״ (H1) מימין, כפתור Outline ״חזרה למשחק״ משמאל, קו מפריד.
- אזור ניקוד ממורכז, ללא Card: ״הניקוד שלך״ (מודגש) ומתחתיו המספר בגודל גדול ומודגש (בחירת מימוש: כ-64px, 700 — DESIGN לא הגדיר גודל).
- קו אופקי, ואז ״חוקי המשחק״ (H2) ממורכז.
- שש פסקאות Body (16/24) מיושרות לימין, בלי מספור או תבליטים, בסדר ובנוסח של DESIGN.md:
  1. צפו ברצף האורות והצלילים וחזרו עליו באותו סדר.
  2. בכל שלב נוסף צבע אחד לסוף הרצף.
  3. יש 10 שלבים. כל שלב שהושלם מזכה בנקודה.
  4. טעות אחת מסיימת את המשחק.
  5. השלמת כל השלבים היא ניצחון בניקוד 10.
  6. אין מגבלת זמן לתשובה.
- גלילה אנכית רגילה של העמוד כשהתוכן ארוך; אין הקטנת גופן ואין גלילה אופקית (`overflow-wrap` לטקסט).
- הטקסט נקבע עם `textContent` בלבד.

> **נוסח הפסקה השנייה:** ״בכל שלב נוסף צבע אחד לסוף הרצף״, כמו בסיימון המקורי וכמו שהמשחק עובד. הנוסח הישן שמופיע בתמונות (״רצף אקראי חדש באורך השלב״) אינו בתוקף, כפי שמצוין ב-DESIGN.md. בבדיקה החזותית מול ה-Mockups, ההבדל בפסקה הזו צפוי ואינו נחשב לסטייה.

## 7. בדיקות

### Vitest
- **Engine:** `pause` מ-`presenting` ומ-`accepting` שומר שלב, ניקוד ורצף ומאפס `inputIndex`; `pause` מ-`idle`/`won`/`lost` לא משנה; `resume` מחזיר ל-`presenting` עם אותו רצף; לחיצה ב-`paused` נדחית.
- **Controller (Fake Timers ו-Audio מדומה):**
  - מעבר לאודות באמצע הצגה: אין יותר `setLit` או צליל, גם אחרי שהזמן מתקדם; `lit === null`.
  - מעבר לאודות באמצע תשובה (אחרי לחיצה נכונה אחת): חזרה מציגה את הרצף המלא מהפריט הראשון, ו-`inputIndex === 0`.
  - מעבר לאודות בדיוק אחרי השלמת שלב (בזמן ההמתנה לרצף הבא): הרצף הבא לא מתחיל מעצמו; בחזרה מוצג הרצף של השלב החדש, עם הניקוד שכבר נצבר.
  - מעברים מהירים חוזרים (בית→אודות→בית→אודות...): בסוף יש ריצת הצגה אחת בלבד, בלי השמעות כפולות.
  - ביקור באודות ב-`idle` ואחרי `won`/`lost`: ה-State זהה לפני ואחרי; אין הצגה.
  - `pageHidden()` במשחק פעיל → `paused`, מסך נשאר `home`; `resume()` מציג אותו רצף; שלב וניקוד ללא שינוי.
  - כשל `unlock` ב-`resume()` → נשאר `paused`, `audioError`, אין הצגה; ניסיון חוזר מצליח.
  - `start()` לא פועל ב-`paused`.

### Playwright (`e2e/about.spec.ts`, על Build, מובייל Chromium)
- Random נשלט במחזור (`0, 0.3, 0.6, 0.9` → כחול, אדום, צהוב, ירוק) כדי שהרצף יהיה מגוון ואפשר יהיה לוודא שמוצג **אותו** רצף. רישום ההארות (כמו רישום הצלילים הקיים) לבדיקת סדר ההצגה.
- אודות לפני התחלה: ניקוד 0, שש הפסקאות בסדר הנכון, אין גלילה אופקית, חזרה → ״התחל״ עדיין מוצג.
- אודות באמצע הצגה ובאמצע תשובה: ניקוד נכון באודות, חזרה → אותו רצף מוצג מתחילתו, המונה לא השתנה, ואפשר להמשיך ולהשלים את השלב.
- אודות אחרי ניצחון/כישלון: הניקוד הסופי מוצג; חזרה → תוצאה ו״משחק חדש״ עדיין שם.
- כפתור Back של הדפדפן מאודות לבית.
- טעינה חדשה בכתובת `#/about` → הבית, ״התחל״, ניקוד 0. רענון באמצע משחק בבית ובאודות → אותו דבר.
- הסתרת דף: דימוי `visibilitychange` (הגדרת `document.visibilityState` / `hidden` ושליחת האירוע) במשחק פעיל → Playback נעצר, ״המשך״ מוצג; לחיצה → אותו רצף, שלב וניקוד ללא שינוי. זו אמולציה; בדיקה אמיתית בנעילת מכשיר תיעשה באבן דרך 5.
- צילומי מסך של שני המסכים ב-Viewport מובייל, לבדיקה חזותית מול ה-Mockups.

### כללי
- כל בדיקות Milestone 1–2 ממשיכות לעבור; `tsc --noEmit` ו-`vite build` עוברים.

## 8. החלטות שיתועדו כ-ADR (בזמן הבנייה)

- **ADR-5: חזרה מאודות דרך Back של הדפדפן.** Back אינו בהכרח מחוות משתמש שמאפשרת חידוש אודיו. ההחלטה: מנסים לחדש ולהציג; אם האודיו נכשל, המשחק נשאר מושהה בבית עם ״המשך״ והודעת התקלה הקיימת. כך לא מוצג רצף בלי צליל ולא נוסף מסך.
- **ADR-6 (אם יידרש): דימוי הסתרת דף בבדיקות.** Playwright אינו יכול להעביר דף לרקע באמת; הבדיקה מדמה את `visibilitychange`, והבדיקה האמיתית במכשיר נשארת לאבן דרך 5.

## 9. סדר העבודה בבנייה

1. Engine: `paused`, `pause`, `resume` + בדיקות.
2. Controller: `screen`, `showScreen`, `resume`, `pageHidden` + בדיקות.
3. Navigation + חיבור ב-`main.ts` (כולל `visibilitychange`).
4. מסך אודות + עדכוני מסך הבית (״המשך״, מצב `paused`).
5. CSS לאודות ולמצב `paused`.
6. Playwright: `about.spec.ts` ועדכון בדיקות קיימות לפי הצורך.
7. הרצת כל הבדיקות, Build, השוואה חזותית לצילומי המסך מול ה-Mockups, תיקונים.
8. ADR ב-ARCHITECTURE.md, סימון 🟡 ב-MILESTONES.md.

## 10. מיפוי ל-Definition of Done

| Back, טעינה חדשה בכתובת אודות, רענון בשני המסכים → בית וניקוד 0 | Playwright |

| בדיקה חזותית של שני המסכים מול ה-Mockups; משחק, Type Checking ו-Build עוברים | צילומי מסך מובייל + כל חבילות הבדיקה + `npm run build` |
